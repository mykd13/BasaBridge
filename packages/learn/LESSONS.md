# Writing and reviewing lessons

This guide is for the people who write Learn lessons and the reading specialist who reviews them (BB-53, BB-74). Lessons are written and checked by people. They are never generated by a model.

The rules come from docs/PLAN.md section 6.3. The schema in `src/lesson.ts` checks every lesson file in CI.

## What we need

One reviewed lesson in each of 33 slots:

- the nine sub-skills: `word_in_context`, `word_parts`, `key_detail`, `sequence`, `main_idea`, `cause_effect`, `feelings`, `prediction`, `conclusion`
- `word_practice` and `decoding`
- in each of three bands: `early` (levels 1 to 30), `middle` (31 to 70) and `advanced` (71 to 100)

See which slots are filled:

```bash
pnpm --filter @basabridge/learn coverage
```

## Start a lesson

1. Copy `lesson-template.json` into `src/lessons/`. Name the file after the lesson id, for example `src/lessons/cause-effect-early.json`.
2. Set `id`, `subject` and `band`. The id is lowercase words joined by dashes, usually the subject then the band.
3. Add the file to the list in `src/lessons/index.ts`. A test fails if a file in the folder is missing from the list.
4. Keep `status` as `draft` while you write. Drafts are checked but never shown to a learner.

## The fixed shape

Every lesson has a goal, then the same four steps in this order.

| Part       | What goes in it                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `goal`     | One sentence in the learner's words about what they will be able to do. Start with "I can".                                     |
| `explain`  | A short explanation of the idea. Two or three sentences.                                                                        |
| `example`  | A tiny English passage, and one sentence (`point`) that shows the idea in it.                                                   |
| `practice` | How many guided practice items to give. The items are generated and checked like stories (BB-54), so you only write the number. |
| `check`    | How many fresh questions to ask with no hints. These are generated too.                                                         |

Practice inside Learn never changes a learner's level. A lesson counts as learned only after the learner does well on fresh questions in their next real story.

## English and Filipino

Every instruction has an English (`en`) and a Filipino (`fil`) version: the title, the goal, the explanation and the example's point. The example passage stays in English, because it is the English text the learner is learning to read.

A draft may leave `fil` empty while the English is written. A reviewed lesson must have both, or CI fails.

## Writing for the band

These are starting points. The reading specialist decides what fits each band.

- **Early (1 to 30):** very short sentences and everyday words. One idea per sentence. The example passage is one or two sentences.
- **Middle (31 to 70):** short sentences, with a new word only when it is the point of the lesson. The example passage is two or three sentences.
- **Advanced (71 to 100):** longer sentences are fine, but keep the explanation brief. The example can be a short paragraph.

In every band:

- Talk to the learner as "you". Keep it kind and plain.
- Do not use names of real children, schools or places a learner could be linked to.
- Do not put level numbers, scores or tries in a lesson. Those live in `packages/levels`.

## Review

Only the reading specialist marks a lesson as reviewed (BB-74 sets up who that is and how they read the drafts).

When the specialist approves a lesson:

1. Set `reviewedBy` to the reviewer's agreed name or role.
2. Set `reviewedAt` to the review date, as `YYYY-MM-DD`.
3. Set `status` to `reviewed`.

CI rejects a reviewed lesson that is missing a reviewer, a date, any Filipino text or any of the four steps. If the lesson changes after review, set `status` back to `draft` until it is reviewed again.
