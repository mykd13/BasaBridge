# Interface text (i18n)

All interface text lives in the catalog in `apps/web/src/i18n/catalog`. Hard-coded strings are a bug (AGENTS.md, golden rule 13, ADR 0004). This page says how the catalog works and how to write the wording.

## How it works

- `catalog/en.ts` and `catalog/fil.ts` hold the same keys. TypeScript fails the build if a key is missing in Filipino.
- Each key has a `standard` wording. It may also have a `simple` wording. Without one, simple falls back to standard.
- Other flags on a key:
  - `spoken`: a fixed sentence that gets pre-generated audio (BB-57). It must not have placeholders.
  - `lowLevel`: shown at levels 1 to 30. Its simple wording must be 8 words or fewer.
  - `reviewed` (Filipino only): a native speaker has checked it.
- Placeholders use ICU syntax, for example `{min}` and plurals. They must match in every language and wording.
- Components use `useTranslations()` or `getTranslations()`. Name the function `t`, so the lint rule knows it is a lookup.

## Which language and wording a page uses

| Viewer     | Language                                         | Wording                    |
| ---------- | ------------------------------------------------ | -------------------------- |
| Learner    | `ReadingHelp.language`                           | `simpleWords` on is simple |
| Parent     | `bb_lang` cookie, then browser language, then en | standard                   |
| Signed out | `bb_lang` cookie, then browser language, then en | standard                   |

The browser language is the `Accept-Language` header. `fil`, `fil-PH` and `tl` map to Filipino. The language switch on signed-out pages calls the server action `setSignedOutLanguage`, which sets the cookie. `<html lang>` follows the language.

Until sign-in (BB-12) and `getMyReadingHelp()` (BB-59) land, `getViewer()` in `i18n/viewer.ts` returns signed out. When they land, return the learner's reading help there.

Stories stay English. Only interface text and its audio are translated.

## Simple wording rules

1. 8 words or fewer at low levels (levels 1 to 30). Count every word, including "a" and "the".
2. Common words only. Pick the word a child of seven would know: "start", not "begin"; "check", not "verify".
3. One instruction per screen. If a sentence has "and" joining two actions, split it across two screens.
4. Active voice, present tense. Say what to do: "Tap Start", not "Start can be tapped".
5. Address the learner directly. No jargon, no abbreviations.
6. Keep the same placeholders as the standard wording.
7. No em dashes or en dashes.

The catalog test enforces rules 1, 6 and 7. Reviewers check the rest.

## Audio

Keys marked `spoken` are exported to `apps/web/src/audio/fixed-sentences.json`, both wordings, for the BB-57 audio build step. After you add or change a spoken key, run:

```bash
pnpm i18n:audio
```

A test fails when the committed file is out of date.

## Hard-coded string check

`eslint-plugin-i18next` (`no-literal-string`) runs on `apps/web/src/**/*.tsx` and `packages/ui/src/**/*.tsx`. It flags JSX text, and `aria-label`, `title`, `placeholder` and `alt` on native elements. On other components it flags every prop except a short allow list in `eslint.config.mjs`. `app/dev/**` and tests are ignored.

Limits to know about: the plugin skips names written in ALL CAPS, and strings that are only digits or punctuation. Strings built outside JSX are not checked. Review those by eye.

## Filipino review

Filipino wording is written by the team and must be checked by a native speaker before it ships to learners. This is human work and is tracked, not automated.

1. Every new Filipino key starts with `reviewed: false`.
2. A native speaker reads the keys that are still `false`. Run `pnpm i18n:unreviewed` to list them. CI prints the same list and never fails on it.
3. The reviewer fixes wording, checks the simple wording against the rules above, and listens to the audio for spoken keys.
4. Set `reviewed: true` on each checked key in the same pull request as the fixes.
5. If the wording of a reviewed key changes, set it back to `reviewed: false`.
